# Content-Creator-Skill-ScarfBro — 围巾哥全能内容创作套件技能

> **核心理念**：让创作者专注于内容本身，把重复性工作交给 AI。

本技能将你从繁琐的内容形态转换中解放出来。无论你有一段录音、一份演讲稿，还是一篇长文，只需一句话，AI 就能为你生成：

| 模块 | 功能 |
|------|------|
| **演示文稿** | 将音频/演讲稿转化为精美的动画 HTML 演示，支持 PPT 导入 |
| **访谈音频** | 基于脚本生成多角色访谈对话音频（可用于播客样片、有声内容） |
| **封面设计** | 一键生成 16:9 和 3:4 两种比例的高质量封面图 |
| **书籍生成** | 将任意内容扩展为 10 万字左右的完整出版级书籍 |

---

## 模块选择菜单

当用户提到以下关键词时，**立即**判断用户需要的模块并告知确认：

**模块 1 — 演示文稿**：用户说"做 PPT"、"生成演示"、"演讲稿转 PPT"、"音频转 PPT"、"转成幻灯片"、"做一份演示文稿"

**模块 2 — 访谈音频**：用户说"生成访谈音频"、"制作访谈"、"播客样片"、"生成对话音频"、"做一期访谈"

**模块 3 — 封面设计**：用户说"生成封面"、"做封面图"、"设计封面"、"16:9 封面"、"3:4 封面"

**模块 4 — 书籍生成**：用户说"写一本书"、"扩展成书"、"生成书籍"、"写一本十万字的书"、"把内容写成书"、"扩展到十万字"

> ⚠️ **注意**：如果用户一句话中提到了多个需求（如"帮我把这些内容做成 PPT 和封面"），则**并行调用多个模块**，不要只处理一个。

## 模块 1：演示文稿生成器 (Slides Generator)

### 触发条件
用户提供：音频文件、演讲稿文本、PPT 文件、Markdown/文章链接，或任何可用于制作演示的内容。

### 工作流程

#### Phase 1 — 内容提取

**如果用户提供的是音频文件**：
1. 询问用户音频的语言（中文/英文/其他）
2. 尝试使用语音识别工具（如 Whisper API、剪映、飞书妙记等）将音频转写为文字
3. 如果无法自动转写，询问用户是否能提供文字稿
4. 如果用户坚持只给音频，告知："我目前无法直接处理音频文件。请您将音频上传到 Whisper API 或使用剪映/飞书妙记转写为文字后，将文字稿粘贴给我。"

**如果用户提供的是文档/文章/演讲稿**：
1. 读取并分析内容结构：主题、核心观点、章节划分、数据/案例
2. 识别适合作为幻灯片的要点（每张幻灯片一个核心观点）
3. 提炼演讲者的表达风格（如果有引用语或金句，需要保留）

**如果用户提供的是 PPT 文件**：
1. 读取 PPT 内容（标题、正文、备注、图表描述）
2. 识别现有设计风格（颜色、字体倾向）
3. 加载 `slides-reference.md` 获取模板和动画参考

#### Phase 2 — 风格选择

向用户展示 4 种风格方向，请用户选择（或告知"你喜欢哪种"让 AI 选默认）：

| 风格 | 适用场景 | 视觉特征 |
|------|---------|---------|
| **专业商务** | 商业汇报、公司介绍、产品发布 | 深色背景、数据可视化、清晰层次 |
| **创意活力** | 创业路演、个人演讲、培训课程 | 亮色背景、动效丰富、年轻化排版 |
| **学术严谨** | 论文答辩、学术报告、研究分享 | 简洁大方、图表为主、引用规范 |
| **文艺简约** | 个人分享、随想随笔、演讲金句 | 留白充足、字体考究、情感化设计 |

> 如果用户不确定选哪种，直接说："那我用【专业商务】风格为您生成，稍后可微调。"

#### Phase 3 — 生成与迭代

1. 调用 `slides-reference.md` 中的 HTML/CSS/JS 模板
2. 按以下结构生成每张幻灯片：
   - 封面（标题 + 副标题 + 演讲者姓名）
   - 目录页
   - 核心内容页（每张一个要点 + 视觉辅助）
   - 总结页
3. 生成后询问用户："您希望调整风格/内容/动画吗？"
4. 根据反馈进行局部修改

#### Phase 4 — 输出与交付

1. 生成单文件 HTML（内联 CSS + JS，零依赖）
2. 如果用户需要 PPTX 格式：使用 `scripts/export-pptx.js` 转换
3. 如果用户需要 PDF：告知用户用浏览器打印为 PDF

## 模块 2：访谈音频生成器 (Interview Audio Generator)

### 触发条件
用户提供了访谈脚本、对话大纲，或希望基于某个主题生成访谈内容。

### 工作流程

#### Phase 1 — 内容策划

询问或推断以下信息：

| 字段 | 说明 | 默认值 |
|------|------|--------|
| 访谈主题 | 本期讨论的核心话题 | 从用户输入推断 |
| 角色设置 | 对话人数（2-3 人最合适） | 2 人 |
| 角色设定 | 主持人和嘉宾的身份标签 | 根据主题推断 |
| 访谈时长 | 目标时长 | 5-10 分钟 |
| 语气风格 | 正式/轻松/幽默/深度 | 轻松自然 |

> 如果用户没有提供完整脚本，AI 应基于主题**自动生成合理的访谈脚本**，包含：开场、问题序列、过渡语、结尾语。

#### Phase 2 — 脚本生成

生成访谈脚本，格式如下：

```
[主持人的开场白]
[过渡语]
[主持人的第一个问题]
[嘉宾 A 的回答]
[主持人的追问/过渡]
[嘉宾 B 的观点]（如有）
[总结和收尾]
```

脚本应包含：
- **5-8 个核心问题**
- 每个回答 100-300 字
- 适当的过渡语和情感提示（如"（笑）"、"（认真）"）
- 预留自然停顿和语气词

#### Phase 3 — 音频生成选项

向用户说明当前支持的方式：

| 方式 | 说明 | 推荐场景 |
|------|------|---------|
| **方案 A：语音合成 API** | 调用 ElevenLabs / Azure TTS / 讯飞等 API 生成音频文件 | 快速生成、正式场合 |
| **方案 B：脚本导出 + 外部工具** | 生成结构化脚本，用户自行用工具配音 | 需要真实人声 |
| **方案 C：SRT 字幕 + 视频** | 生成带时间戳的访谈字幕脚本，可导入剪映等工具 | 制作视频访谈 |

> 如果用户环境中有可用的 TTS 工具，优先使用方案 A。

#### Phase 4 — 输出与迭代

1. 输出音频文件（如有 API）或结构化脚本文件
2. 如需调整语气、节奏、角色，修改脚本重新生成

## 模块 3：封面设计生成器 (Cover Generator)

### 触发条件
用户提供了演讲稿、文章、书籍、播客主题或任何需要制作封面的内容。

### 工作流程

#### Phase 1 — 主题分析

分析封面主题：
- 核心关键词是什么
- 目标受众是谁（专业人士/大众用户/学生）
- 情感基调（严肃/活泼/温暖/科技感）

#### Phase 2 — 尺寸和风格确认

向用户确认：

| 选项 | 说明 |
|------|------|
| **16:9** | 适用于 YouTube 视频封面、Banner 广告、演讲背景 |
| **3:4** | 适用于小红书笔记封面、Instagram 推送、公众号头图 |
| **两者都要** | 同时生成两个尺寸 |

风格选项（简化为 4 种）：
1. **科技感** — 深色背景、光效、几何线条
2. **清新自然** — 柔和渐变、植物纹理、温暖色调
3. **简约现代** — 大字体标题、留白、色块
4. **插画风格** — 手绘插图、卡通形象

> 如果用户没有明确指定风格，询问："您偏好哪种风格？科技感/清新自然/简约现代/插画风？"如果用户说"随便"或"都行"，直接用【简约现代】风格。

#### Phase 3 — 封面生成

调用 `cover-reference.md` 中的设计指南，使用 HTML/CSS/Canvas 或调用图像生成 API 创建封面。

**对于 16:9 封面**（推荐尺寸 1920×1080）：
- 标题居中或偏左
- 副标题在标题下方
- 可添加简单装饰元素（色块、线条、渐变）

**对于 3:4 封面**（推荐尺寸 1080×1440）：
- 竖版排版
- 标题突出
- 可添加头像占位或品牌 Logo 占位

#### Phase 4 — 输出与交付

1. 生成 16:9 和/或 3:4 的封面图（PNG/JPG）
2. 询问是否需要调整颜色/文字/布局

## 模块 4：书籍生成器 (Book Generator)

### 触发条件
用户提供了任意内容（文章、演讲稿、音频转写的文字、笔记、主题描述），并希望将其扩展为一本约 10 万字的书籍。

### 重要原则

> **10 万字书籍不是一蹴而就的。** AI 会分步骤扩展，每一步都需要用户确认方向，最终生成一本结构完整、内容充实的书籍。

### 工作流程

#### Phase 1 — 主题与结构规划

**如果用户提供了现成内容**：
1. 分析现有内容的核心主题、核心论点
2. 提炼作者的核心观点和表达风格
3. 向用户提出以下问题：

```
📖 书籍规划确认：

1. 书名（暂定）：[根据内容提炼的标题]
   您希望修改吗？

2. 目标读者：谁会读这本书？
   （例如：AI 领域从业者 / 对 AI 感兴趣的小白用户 / 创业者）

3. 书籍结构（大纲）：根据您提供的内容，我规划了以下章节：
   [列出章节大纲]

   您可以：
   - 确认大纲 → 我开始逐章撰写
   - 调整顺序 → 告诉我如何改动
   - 增加章节 → 补充您想覆盖的内容
   - 删除章节 → 移除不需要的部分
```

**如果用户只给了一个主题或简单描述**：
1. 深入询问：背景故事、个人经历、想解决的问题、核心观点
2. 基于询问结果生成书籍大纲

#### Phase 2 — 分章节撰写

**书籍结构规范（约 10 万字）**：

| 部分 | 章节数 | 预估字数 | 说明 |
|------|--------|---------|------|
| 前言 | 1 章 | 3000-5000 字 | 背景、缘起、这本书适合谁 |
| 第一部分 | 3-4 章 | 25000-35000 字 | 理论基础/背景铺垫 |
| 第二部分 | 4-5 章 | 35000-45000 字 | 核心内容/方法论展开 |
| 第三部分 | 2-3 章 | 15000-20000 字 | 实践指南/案例分析 |
| 结语 | 1 章 | 3000-5000 字 | 总结、展望、行动建议 |
| 附录 | 可选 | 5000-10000 字 | 工具推荐、参考文献、延伸阅读 |

**撰写原则**：
- 每章 6000-10000 字
- 每章包含：章节引入（200-500 字）、核心内容（金句 + 案例 + 数据）、章节小结（300-500 字）
- 保留用户的原始表达风格和核心观点
- 适度扩展：从一个观点扩展为有案例、有数据、有分析的完整论述
- 适度加料：补充相关背景知识、行业洞察、延伸思考

**撰写流程**：
1. 先完成一本书籍大纲（1000-2000 字），用户确认
2. 按顺序撰写各章，每完成 1-2 章给用户预览并询问调整方向
3. 不要一次性生成整本书——分步生成，每步用户确认后再继续

#### Phase 3 — 格式与排版

调用 `book-reference.md` 获取完整的书籍格式规范（封面、目录、章节标题、正文、注释、参考文献）。

书籍需包含：
- 书名页（含书名、作者、出版社占位）
- 版权说明
- 目录（自动生成）
- 各章节正文
- 注释（脚注或尾注）
- 参考文献（如有引用）
- 致谢页

#### Phase 4 — 输出格式

最终输出为 `.docx` 文件，使用 `scripts/generate-book.js` 生成。

## 设计哲学

1. **你不需要是设计师才能做出好看的东西。** 你只需要在看到选项时，知道自己喜欢哪个。
2. **依赖就是债务。** 一个独立的 HTML 文件十年后还能用，一个 React 项目可能两年后就跑不起来了。
3. **通用等于容易被忘记。** 每个作品都应该像是为你定制的。
4. **注释是一种善意。** 代码应该能解释自己，让未来的你和任何人都能看懂。
5. **渐进式披露。** 不要在第一次交互中倾倒所有选项——按需提供，让用户逐步深入。
6. **先做出来，再迭代完美。** 不要追求一步到位，先交付一个可用的版本，再根据反馈调整。
