# 论文多格式分析助手

从同一篇论文整理文字、词频、引用、网页、幻灯片和播客等多种交付物。

| 项目 | 内容 |
|---|---|
| 分类 | 学术研究 |
| 适合什么时候 | 同一篇论文需要两种以上格式、词频统计或播客解读时使用；仅需深度长文时使用论文深度解读。 |
| 需要提供 | arXiv 链接或论文 PDF；所需输出清单 |
| 可以得到 | 分析摘要、词频表、引用表及所选媒体文件 |
| 能力说明 | 需媒体工具；原版脚本缺失 |
| 兼容调用标识 | `$paper-analysis-assistant` |

## 直接这样说

> 请用论文多格式分析助手，输出这篇论文的摘要、引用表和双人播客脚本。

## 核心方法

1. 识别用户所需产物，只做选定项目；没有格式要求时先提供摘要和可选产物，不自动生成全部媒体。
2. 获取并阅读论文全文，保留标题、作者、版本、链接和读取范围。使用当前 PDF 工具提取文本；原版 scripts 目录不存在，不能直接调用示例命令。
3. 词频统计需实际计算，注明大小写归一、分词、停用词和统计范围；没有停用词表时使用明确声明的规则。输出词频 CSV，不将词频当成论文贡献。
4. 提取引用并记录来源、链接和核验状态；摘要区分作者结果和解释。
5. 网页、幻灯片和总结图分别调用当前可用的网页、演示文稿及图像工具。PPT 要验证文件可打开和页数，图表数值与原论文一致。
6. 播客先写主持人—嘉宾脚本，准确解释方法、证据与局限；有可用语音工具再生成音频，没有则交付脚本并说明音频尚未生成。仅在真实生成音频后提供音频时长和播放文件。
7. 用索引列出每个实际生成文件及用途。

## 安装与能力边界

原文所列下载、提取、词频、语音、播客、HTML、PPT、引用脚本和 stopwords.txt 均未提供；采用当前可用能力逐项完成，不保证原版批处理链。

安装包通过结构检查不等于完整功能已经实测。调用时还会检查文档、图像、语音等实际工具。界面名称为中文，内部标识和 SKILL.md、agents/openai.yaml 等必要文件名保留标准格式。
