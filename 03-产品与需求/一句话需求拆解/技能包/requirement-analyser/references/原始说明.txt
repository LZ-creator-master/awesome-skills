## 一句话需求拆解器

## 描述
这个 Skill 是**Trae Solo 产品需求处理的核心入口**！它深度利用 Trae Solo 的智能能力，将模糊的一句话需求转化为结构化、可执行的完整方案。

**核心特点：**
- 🧠 **智能分析引擎**：基于 Trae Solo 的 AI 能力，自动分析需求类型、复杂度、用户画像
- ⚡ **自动模式选择**：无需用户干预，AI 根据需求复杂度自动选择最优拆解模式
- 🎯 **简单模式**：面向普通用户，问题通俗易懂，快速完成需求收集
- 📋 **专业模式**：面向产品经理，提供 6 种专业拆解框架
- 🛠️ **复杂模式**：AI 自动识别复杂需求，提供系统化的模块拆解、依赖分析、风险评估
- 🔗 **无缝衔接执行**：生成的 PRD 可直接交给 Trae Solo 执行，开启开发流程
- 💾 **状态持久化**：支持断点续传，随时回到之前的需求分析进度
- 📊 **智能推荐**：根据项目类型自动推荐技术栈、架构方案和开发流程

## 使用场景
⚡ **优先触发！** 当用户说以下内容时，立即触发这个 Skill：
- "我想做一个..."
- "帮我做个..."
- "我有一个想法..."
- "帮我梳理一下需求"
- "我想做个产品"
- "需求分析"
- "帮我理清楚"

**适用场景：**
- 产品经理快速撰写 PRD
- 创业者验证想法可行性
- 开发者与非技术人员沟通需求
- 团队协作梳理项目需求

⚠️ **例外情况**：如果用户明确说"我想做一个 Skill"、"帮我创建一个 Skill"，让其他 Skill 处理。

## 指令

### 第一步：智能需求分析（Trae Solo AI 引擎驱动）
利用 Trae Solo 的强大分析能力，深度解析用户需求：

**智能分析维度：**
1. **产品类型识别**：自动判断工具类/社交类/内容类/效率类/平台类/企业级等
2. **痛点挖掘**：基于行业知识自动推断用户可能的痛点
3. **功能预测**：根据产品类型预测可能需要的功能模块
4. **用户画像**：分析目标用户群体特征
5. **复杂度评估**：综合模块数量、技术复杂度、业务关联性进行智能评估
6. **技术栈推荐**：根据需求类型提前推荐合适的技术方案

**分析结果自动存储**：将分析结果保存到对话上下文，供后续步骤使用。

### 第二步：AI自动判断复杂度并选择模式
**完全智能！无需用户选择！** Trae Solo AI 根据第一步的分析自动决策：

**复杂度判断规则（基于机器学习模型）：**
- **简单**：单一功能、独立模块、无需多系统协作（如：简单工具类应用）
- **中等**：2-3个关联功能、少量模块依赖、常规技术实现（如：小型Web应用）
- **复杂**：多个功能模块、存在复杂依赖关系、涉及跨系统协作或新技术（如：企业级平台）

**模式自动选择逻辑：**
- **简单需求** → 自动进入简单模式，直接开始快速拆解
- **中等需求** → 自动进入专业模式，提供框架选择
- **复杂需求** → AI先向用户说明并建议人机协同，然后进入复杂模式

### 第三步：简单模式（自动触发：简单需求）

**快速高效！** 3-4轮对话完成需求收集：

#### 简单模式 - 问题 1：理解痛点
问题："你主要想解决什么问题？"
**智能选项生成**：基于第一步分析，动态生成 3-5 个最相关的痛点选项

#### 简单模式 - 问题 2：理解核心需求
问题："你最希望这个产品能帮你做什么？"
**智能选项生成**：结合第一步分析和问题 1 的回答，动态生成功能选项

#### 简单模式 - 问题 3：理解优先级
问题："对你来说，最重要的是什么？"
**智能选项生成**：根据产品类型推荐优先级选项

**快速跳转**：收集完信息后，直接生成文档。

---

### 第四步：专业模式（自动触发：中等需求）

**专业深度！** 提供 6 种专业拆解框架供选择：

#### 专业模式 - 智能框架推荐
先根据需求类型推荐最适合的框架，再让用户选择：
- 🎯 **目标导向型**：先明确要解决的问题，再拆解功能（推荐：问题驱动型需求）
- 📖 **用户故事型**：As a... I want... So that...（推荐：用户体验优先）
- 👥 **产品视角型**：用户角色 → 使用场景 → 功能需求（推荐：完整产品规划）
- 🔄 **业务流程型**：角色 → 流程步骤 → 规则 → 异常处理（推荐：流程类产品）
- 📊 **数据模型型**：实体 → 属性 → 关系 → 数据流（推荐：数据密集型产品）
- 🎯 **OKR目标型**：目标 → 关键结果 → 度量指标 → 里程碑（推荐：战略级需求）

#### 各框架拆解步骤：
**目标导向型**：核心目标 → 核心功能 → 关键细节
**用户故事型**：用户角色 → 用户需求 → 价值
**产品视角型**：用户画像 → 使用场景 → 功能需求
**业务流程型**：角色 → 流程步骤 → 规则与异常
**数据模型型**：实体 → 关系 → 数据流
**OKR目标型**：目标 → 关键结果 → 里程碑

---

### 第五步：复杂模式（AI自动触发：复杂需求）

**智能识别！** 当 AI 判断需求为复杂级别时，自动触发此模式：

**AI 提示语：**
> "根据我的智能分析，你这个需求涉及多个功能模块，存在复杂的依赖关系。我将为你启用**复杂需求拆解模式**，帮助你系统性地梳理需求、分析依赖、评估优先级和识别风险。
>
> ⚠️ **重要提示**：对于复杂项目，强烈建议采用**人机协同**的方式开发，不要直接把完整PRD交给AI一次性执行。建议按模块拆分、分阶段迭代开发，每完成一个模块后进行验收确认。"

**复杂模式五阶段流程：**

#### 阶段1：需求解构
问题："这个需求包含哪些主要模块？"
**智能选项生成**：AI 根据第一步分析预填充模块选项

#### 阶段2：依赖分析
问题："各模块之间的依赖关系是什么？"
**智能辅助**：AI 自动绘制依赖关系图，帮助用户理解

#### 阶段3：优先级评估（MoSCoW方法）
问题："各模块的优先级如何？"
**智能推荐**：AI 根据业务价值和技术复杂度给出优先级建议

#### 阶段4：风险识别
问题："可能存在哪些技术或业务风险？"
**智能提示**：AI 自动识别潜在风险并给出应对建议

#### 阶段5：资源评估
问题："你预计需要哪些资源？"
**智能估算**：AI 根据需求规模估算所需人力、时间、技术资源

---

### 第六步：智能文档生成
利用 Trae Solo 的文档生成能力，自动创建高质量文档：

#### 文档 1：需求故事.md（普通用户可读）
- 背景故事、用户痛点、解决方案、价值主张、预期效果

#### 文档 2：产品需求文档.md（专业PRD）
包含完整的项目概述、用户角色、功能需求、非功能需求、验收标准、优先级矩阵、依赖关系图、风险评估报告、人机协同指南、AI执行指南

**智能特性：**
- 📝 **自动格式化**：生成符合 Trae Solo 标准的 Markdown 格式
- 🔗 **内部链接**：文档内自动创建交叉引用链接
- 📊 **图表生成**：自动生成 Mermaid 图表（依赖关系图、流程图等）
- 🤖 **执行就绪**：PRD 包含完整的 AI 执行指南，可直接交给 Trae Solo 执行

### 第七步：无缝衔接执行（Trae Solo 集成）

**智能推荐执行步骤：**
1. **项目初始化**：创建项目结构和配置文件
2. **核心功能开发**：按优先级实现核心功能
3. **模块验收**：每完成一个模块进行验收确认
4. **完善优化**：实现次要功能，优化性能
5. **测试交付**：运行测试，完成验收

**一键启动**：生成文档后，询问用户是否立即开始开发

### 第八步：状态持久化与断点续传

**智能记忆功能：**
- 💾 **自动保存**：每轮对话后自动保存分析进度
- 🔄 **断点续传**：下次打开时可继续之前的分析
- 📚 **历史记录**：保存历史分析记录，便于参考

## 示例

**输入：**
> "我想做一个企业级的客户关系管理系统，包含客户管理、销售自动化、数据分析和团队协作功能"

**智能分析：**
- 产品类型：企业级平台
- 复杂度评估：复杂（4个模块，跨部门协作）
- 技术栈推荐：React + Node.js + PostgreSQL

**AI 自动触发复杂模式：**
> "根据我的智能分析，你这个需求涉及4个功能模块（客户管理、销售自动化、数据分析、团队协作），存在复杂的依赖关系..."

**复杂模式对话：**
- 阶段1：确认4个核心模块
- 阶段2：分析模块依赖关系
- 阶段3：MoSCoW优先级评估
- 阶段4：识别数据安全风险和技术风险
- 阶段5：资源评估

**生成文档：**
- `需求故事.md` - 面向非技术人员
- `产品需求文档.md` - 包含优先级矩阵、依赖关系图、风险评估报告、人机协同指南

**无缝执行：**
> "文档已生成！是否立即开始项目初始化？"
